That single sentence is why Figma Make keeps failing you. Asked for glass, it reaches for backdrop-filter: blur(), a white border, and a gradient overlay — and it will never get there, because those three things cannot bend light. The prototype you sent doesn't use any of them. It hands the whole job to a WebGL fragment shader.

Below is what that shader actually does, every property you named mapped to the exact line that produces it, and a spec you can paste into Make to get it built correctly the first time. Everything here has been run — I rebuilt the shader as a reusable component and diffed it against the original pixel for pixel.

Why backdrop-filter can never do this

backdrop-filter lets an element blur what's behind it. It does not let the element read what's behind it. Refraction means sampling the backdrop at a displaced coordinate — the pixel you draw at the rim comes from somewhere else on the background. CSS has no mechanism to express that. Neither does SVG feDisplacementMap, usefully, because it can't reach the live page behind the element.

So the backdrop has to become something the shader can address: a texture. And that forces the architecture — one canvas, holding both the background and the glass, with the glass composited in the fragment shader. There is no version of this where the glass is a <div> sitting on top of a background.

The load-bearing idea

A liquid-glass element is not a layer over the background. It is a region of the background, resampled. Every technique below follows from that.

The five mechanisms that carry the look

1 · The shape is a distance field, not a rectangle

Nothing is drawn. For every pixel the shader computes a signed distance to the shape's edge — negative inside, zero on the boundary, positive outside. That single number drives the fill mask, the refraction, the highlight, and the shadow. It's why the effect works identically on a pill, a circle, or a star. 

// signed distance to a rounded rectangle, in pixels
float sdRoundRect(vec2 p, vec2 half_, float r) {
  vec2 q = abs(p) - half_ + r;
  return min(max(q.x, q.y), 0.0) + length(max(q, 0.0)) - r;
}

2 · One normalized edge field drives everything

The distance gets remapped to 0 at the shape's center and 1 at its rim, then raised to a power. That exponent is what you experience as glass thickness — it crushes all the interesting behavior into a narrow band at the edge, which is exactly where real glass does its work. 

float edge = clamp((sdf / halfHeight) + 1.0, 0.0, 1.0);  // 0 center → 1 rim
float falloff = pow(edge, u_depth);                    // ★ was a literal 12.0
Change one number first

If you only ever expose a single parameter, expose depth. Sweeping that exponent from 4 to 24 moves the material from thick pressed crystal to a thin sheet of window glass, and it costs one uniform.

3 · Frost must vary across the surface

This is the detail that separates convincing glass from frosted plastic, and it's the one an AI tool will always miss. The blur is not uniform. It's heavy through the body and collapses to almost nothing at the rim, so the edge stays crisp enough to refract: 

float mip = mix(3.5 * u_frost, 1.5, falloff);
//              ^ body: heavy    ^ rim: sharp

The blur itself is stochastic, not Gaussian: nine taps at hash-jittered offsets. Cheap, and the faint grain reads as material rather than as a filter.

4 · Dispersion is asymmetric on purpose

Splitting R/G/B by equal amounts gives you the cheap 3D-movie look. Real glass disperses unevenly, and the prototype fakes that with a deliberate ×1.2 / ×0.8 imbalance along the radial axis. Keep the asymmetry; it's most of the realism. 

r = texture2D(tex, uv + dir * amt * 1.2).r;   // pushed out
g = texture2D(tex, uv).g;                        // reference
b = texture2D(tex, uv - dir * amt * 0.8).b;   // pulled in

5 · The highlight needs a light direction — and the original's is broken

The prototype computes its sheen as abs(dot(normal, lightDir)). Because of that abs(), the highlight is an axis, not a direction: 135° and 315° render identically, as do 45° and 225°. Wire a light-angle slider to it as-is and half the dial does nothing — which reads as a broken control.

Drop the abs() and use the signed dot product, then add the opposite rim back at reduced strength. Real glass does catch light where it exits, just more faintly: 

float d = dot(grad, lightDir);
float lit   = 1.0 - pow(1.0 - clamp( d, 0.0, 1.0), 0.5);
float unlit = 1.0 - pow(1.0 - clamp(-d, 0.0, 1.0), 0.5);
spec = (lit + unlit * u_counterLight) * pow(falloff, u_splay);

With that fixed, angles land in standard orientation: 0° right, 90° top, 180° left, 270° bottom. Apple's own glass sits around 135° — upper-left — which is the vector the prototype hardcoded.

What to tell Figma Make

Make will not invent this correctly from a description like "add a liquid glass button," because its instinct is CSS and the actual answer is 200 lines of GLSL. Two things reliably work.

The reliable path: paste the finished component into your project and tell Make to use it rather than to build it. Prototypes accept new files; use that. The second-best path is the spec below, which front-loads the architecture so Make can't default to backdrop-filter: 

Build a liquid glass element as a WebGL fragment shader. Do NOT use
backdrop-filter, box-shadow, borders, or gradient overlays — none of them
can refract, and the effect depends on refraction.

ARCHITECTURE (non-negotiable)
- ONE <canvas> renders BOTH the background image AND the glass.
- Load the background as a WebGL texture; the shader samples it at
  DISPLACED coordinates to refract. The glass is a region of the
  background, resampled — not a layer on top of it.
- Define the glass shape as a signed distance field (SDF). Derive the
  fill mask, refraction, highlight and shadow from that one SDF.
- Render labels/icons as absolutely-positioned DOM ABOVE the canvas.
  Do not draw text in the shader.

REQUIRED UNIFORMS (all must be props, none hardcoded)
  lightAngle 0-360   lightIntensity 0-1   counterLight 0-1
  refraction 0-3     depth 4-24           dispersion 0-4
  frost 0.1-3        splay 1-14           saturation 0-1.2
  luminance 0.6-1.6  tint rgb             innerShadow 0-0.6
  dropShadow {intensity, x, y, blur}      cornerRadius

CRITICAL DETAILS — get these wrong and it looks like plastic
1. Normalize the SDF to 0 at center / 1 at rim, then raise to `depth`.
   Drive refraction AND highlight from that falloff so both are
   confined to a rim band.
2. Frost must VARY: mip = mix(3.5 * frost, 1.5, falloff). Heavy in the
   body, near-zero at the rim. A uniform blur ruins it.
3. Dispersion must be ASYMMETRIC: R at +1.2x offset, B at -0.8x.
4. Highlight uses the SIGNED dot product of the rim normal and the
   light vector, never abs() — abs() makes the angle 180°-periodic.
5. Composite the drop shadow into the background BEFORE the glass.

WEBGL REQUIREMENTS (silent black screen if missed)
- Request OES_standard_derivatives AND emit
  `#extension GL_OES_standard_derivatives : enable`. Provide a manual
  finite-difference fallback when unavailable.
- `precision mediump float;` at the top of the fragment shader.
- Set crossOrigin='anonymous' on the image before texture upload.
- Backgrounds are non-power-of-two: CLAMP_TO_EDGE + LINEAR, no mipmaps.
- Multiply canvas.width/height by devicePixelRatio, and scale EVERY
  pixel-valued uniform by dpr too.
- GLSL ES 1.0 needs constant loop bounds — no `i < uniform`.
- Memoize the props/uniforms objects; an inline object literal in the
  parent re-runs the setup effect every render and the canvas stays blank.

Failure catalog

Every one of these produces a blank, black, or plastic result with no error message, which is why this effect is so miserable to debug in a prototyping tool. I hit four of them building the version above.

Canvas renders solid white or blank
The parent passes an inline object as props. The prototype's setup effect depends on backgroundMedia; a fresh object each render rebuilds the texture forever, so it never advances past its white placeholder. Fix: wrap props in useMemo. This one bit me and produces zero console output.
Canvas renders solid black
Either a missing crossOrigin = 'anonymous' (the texture upload throws a security error), or non-power-of-two texture defaults. Fix: set crossOrigin before .src, and always CLAMP_TO_EDGE + LINEAR.
Glass is flat — no rim, no bevel
dFdx/dFdy used without enabling derivatives. Fix: call getExtension('OES_standard_derivatives') and emit the #extension pragma as the shader's first line. Make routinely writes one without the other.
Shader won't compile, no visible reason
A uniform used before it's declared, a loop bound by a uniform, or a missing precision line. Fix: read getShaderInfoLog() — it gives you the exact line. Always log it; silence here is the default.
Glass drifts from its label on a Retina display
Position scaled by devicePixelRatio but size not — the original's actual bug. Its u_mouse is dpr-multiplied while u_width/u_height aren't, so the "385px" slider only looks right at exactly dpr 2. Fix: scale every pixel uniform by dpr, consistently.
Saturation slider barely does anything
Faithful to the original, and still surprising: saturation is mixed by edgeFalloff, so it only affects the rim band while the body keeps full color. Fix, if you want a real control: apply it to glass before the mix, not inside it.
Frame rate collapses
The prototype's drop shadow brute-forces a 31×31 loop — 961 SDF evaluations per pixel, every frame. Fix: the SDF is already a distance, so use it — 1.0 - smoothstep(-blur, blur, shadowSDF). One evaluation, visually equivalent. That's what the demo above runs.
Exported project won't npm install
Not a shader issue, but it will stop you cold. Figma Make exports pin versions inside import specifiers (lucide-react@0.487.0) and mirror them as "pkg@1.2.3": "npm:pkg@1.2.3" in package.json — npm rejects those as invalid package names. Fix: delete the aliased duplicate keys, then add a Vite resolveId hook that strips the version suffix back to the real package name.

Scaling to an actual interface

Here's the constraint that matters for real work, and the reason you can't just drop this component next to your existing components: a canvas cannot see its DOM siblings. Give every glass button its own canvas and each one refracts only its own background — a nav bar over your scrolling content will refract nothing, because there's nothing in its texture.

So one surface owns the backdrop and draws every glass element into it, unioned with min() over their distance fields. I built and ran this — four elements, one canvas, DOM labels registered on top: 

// union of N shapes; also track whose half-height owns this pixel,
// because the edge field normalizes by the OWNING shape's size
void sceneSDF(vec2 frag, out float sdf, out float ownerHalfH) {
  sdf = 1e9; ownerHalfH = 1.0;
  for (int i = 0; i < COUNT; i++) {   // COUNT baked in at compile time
    float d = sdRoundRect(frag - u_rects[i].xy, u_rects[i].zw, u_radii[i]);
    if (d < sdf) { sdf = d; ownerHalfH = max(u_rects[i].w, 1.0); }
  }
}

Drive the SDF rects and the DOM overlay from the same array of numbers. That's what keeps the glass and its content from drifting apart — there's no second source of truth to get out of sync.

Because COUNT has to be a compile-time constant in GLSL ES 1.0, the shader recompiles when the number of elements changes. Fine for a prototype; keep a fixed MAX_SHAPES and pad if you'd rather not.

Where to stop

Be honest about the cost. This is a full-screen fragment shader running every frame, and it cannot refract live DOM — no scrolling text, no video elements, no other components behind the glass unless they're in the texture.

SituationUse
Hero moment, one or a few glass elements over an image or video The full shader. This is what it's for, and it's genuinely convincing.
A composed glass UI — nav, cards, buttons over one backdrop One GlassSurface, N shapes unioned, DOM content above.
Glass over live scrolling content or a form Don't. Use backdrop-filter: blur(20px) saturate(180%) with a 1px inset highlight. No refraction, but honest and cheap.
Presenting on unknown hardware Keep a CSS fallback behind a getContext('webgl') check. Integrated GPUs and low-power mode will struggle.
The short version

Refraction requires resampling, resampling requires a texture, a texture requires one canvas that owns the backdrop. Give Make that architecture explicitly and it can build the rest. Ask it for "glass" and you'll get a blurred div every time.
